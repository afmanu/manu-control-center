# Review work, decisions and useful next steps

Use this mode only when requested. Read the workspace/project routes and relevant source evidence, outputs, decisions and prior review. Follow the user's selected scope and dates. For daily/weekly reviews, derive the actual day or explicit week boundaries from the host clock when not supplied; do not infer work or reading history from file modification times. A partial week remains partial.

Use the [review template](templates/review.md). Reuse an existing same-scope, same-period review instead of adding a duplicate. Update an editable review with meaningful new evidence; preserve accepted earlier artifacts through a linked revision. State which sources/time span were checked and what could not be verified.

- **Daily/weekly:** distinguish work actually evidenced, confirmed decisions, open loops and proposed next actions. Link useful outputs, carry unresolved items without fabricating progress, and identify one reasonable next priority grounded in the user's context. Missing records are unknown, not proof nothing happened. Save dated continuity and its project route. Do not create a schedule.
- **Decision outcome:** retain the original choice, date, rationale, alternatives and review condition. Link observed outcomes and compare them to the intended result; keep interpretation separate from evidence. A future review trigger or missing outcome remains pending. Do not invent success/failure, rewrite the original rationale or replace a decision because an alternative now sounds better.

Keep project-specific conclusions local and sources intact. A review is not automatic global-memory promotion, a merge, external delivery or an authorization to act on every suggestion. On no-save, answer in chat without review, hub or session edits. Read back sources and continuation routes before reporting completion.
