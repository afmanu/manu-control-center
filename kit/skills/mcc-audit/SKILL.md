# Audit useful operation

Read [shared guidance](../../operating-guide.md), the workspace map, relevant priorities and the previous scoped audit. Follow declared routes before fallback search. Inspect only the selected scope and useful neighbors. A folder, skill name or listed connection is not evidence of successful work.

Use the [audit template](../../templates/audit.md). Check the following as relevant to the request:

- Can the agent find the authoritative context, selected source, intended output and next action from the entry/hub? Check exact paths, headings, aliases and useful return routes. Record when fallback search succeeds but the declared route fails.
- Does an important workflow have an actual useful sourced result, correct decision/proposal status, working resources and a repeat/continuation route? Distinguish installed, discovered and exercised capabilities. Inspect evidence or make a bounded read-only probe; do not launch substantive paid work just to audit it.
- Does each relevant connection record authority, access mechanism, checked evidence/date and limits? Missing access evidence remains unverified; it is not proof the service is broken. Do not inspect credentials or activate a connection.
- Does retained context preserve source authority, corrections, unresolved conflicts, scopes and accepted predecessors? Are important notes and outputs reachable? Report actual coverage rather than claiming a global refresh.
- Is manual or scheduled operation appropriate to the user's selected work? Manual use is valid. Do not penalize a missing unwanted scheduler or create one.

## Consolidation mode

When requested, look for conceptual overlap despite different titles, undistilled resources, repeated useful insights, unlinked decisions and hubs with no useful continuation. Read candidates; shared words or file age alone prove neither duplication nor neglect. Distinguish a useful retained source from a source that could yield new reusable knowledge. Record merge/distillation/link proposals with evidence and a concrete benefit. Do not merge, delete, rename or archive notes during the audit.

## Findings and history

Save in the mapped maintenance/audit location, using one scoped report with stable finding references and dated check history unless an established convention differs. Reuse prior IDs for the same issue; never renumber open findings to make a fresh report. Each finding records its affected path/workflow, evidence, impact, state (`open`, `unverified`, `resolved`), proposed remedy and completion check. Record scope changes; carry prior open/unverified items forward unless evidence changes them. A proposal is not a verified defect.

Only mark resolved after the relevant route/workflow is rechecked successfully; retain the prior failure and new evidence. A selected recheck must not close untested findings. Save the report and its maintenance index route as part of the requested audit, preserving inspected work. On no-save, return it in chat. Suggest the most useful next repair based on evidence; use `mcc-improve` only when repair is requested. Do not inflate scores, require a fixed number of problems or turn an audit into a discovery interview.
