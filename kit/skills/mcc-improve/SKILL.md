# Improve one useful capability

Read [shared guidance](../../operating-guide.md), the workspace map and the selected finding/request with its sources. Reuse known priorities. Choose one useful improvement per cycle; if the user explicitly requests several, handle them as separate bounded changes. A concrete request does not need another interview, KPI exercise or feature-selection step. Clarify only a blocking ambiguity.

Choose the relevant mode:

- **Repair:** follow the finding's exact failed route/workflow and inspect its expected target. Reuse `mcc-link` or the existing work procedure for an authorized local fix. Preserve unrelated text, source meaning and accepted artifacts. Re-run the failed probe from its normal entry before recording resolution under the same finding ID. Keep untested findings open/unverified.
- **Inspect/adapt/build a skill:** follow the [extension recipe](../../extend.md). Search existing capabilities first; an overlapping request should reuse or improve the existing definition. A catalog entry alone is not an installed or exercised capability.
- **Consolidate selected knowledge:** read audit proposals and use `mcc-synthesize`/`mcc-link` for the explicitly chosen distillation or connections. Preserve sources and uncertain claims. A general request to improve does not authorize deleting or merging all apparent duplicates.
- **Update/repair installed instructions:** follow the [update procedure](../../update.md), with old/current/new source comparison and a readable progress/conflict record. The installation copier is not an overwrite tool.
- **Save a tool or SOP guide:** use the [SOP template](../../templates/sop.md) for a process actually used or supplied. Record purpose, trigger, source/tool routes, steps, output/checks, failure behavior and relevant verification date. Label unverified or outdated tool instructions; verify volatile details through the host's current official documentation when possible. Do not store secrets, enable integrations or create schedules.

Read back changed files and the useful result, then record the scoped change, actual check and remaining gaps in the existing maintenance history. Use the [improvement template](../../templates/improvement.md) when needed. Ensure findings, new skills and SOPs can be found through the appropriate workspace/project route. A successful edit alone does not prove a successful workflow. No-save returns proposals in chat without edits or saved history.
