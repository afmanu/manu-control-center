# Capture without losing meaning

Read [shared guidance](../../operating-guide.md), the workspace routes and the relevant project hub. If the input should not be retained, answer in chat without writing it anywhere.

Search the relevant source/note locations before creating a file. If the same content and origin already exist, reuse the note and report its path. For a changed version, preserve the original and record the new source/version relationship; do not overwrite raw evidence. Preserve the distinctions between an agreement, proposal, question, reference and assistant interpretation. Keep project-specific facts out of global context.

Use the existing note conventions or the [source template](../../templates/source.md). Include origin (file, supplied text or URL), source/capture dates when known, scope and the exact relevant supplied content or a clearly labeled faithful excerpt. Never invent a source date. Separate any capture summary from source wording. K1 accepts provided text and local UTF-8 files; fetching URLs is a later capability, so an unverified URL can be recorded only as a reference.

Write in the mapped capture location, linking the relevant existing hub. Add a concise hub route when authorized and missing. Resolve ambiguous destinations only if existing context cannot settle them. Do not create a note for every mentioned concept, pretend heuristic links are validated, or add private information to public outputs. The request authorizes the necessary local capture; do not ask again just to save it.

Read the note back, verify its origin/content and follow added links before reporting success. If saving fails, state the actual remaining gap. Do not describe a report or captured assertion as verified permanent knowledge.
