# Distill understanding that helps work

Read [shared guidance](../../operating-guide.md), the workspace map, selected project/area and relevant original sources. Infer an unambiguous scope from the request; clarify only a blocking ambiguity. Search existing knowledge before adding a note, including relevant older material. Do not equate age with unread status or inactivity.

Separate source summaries, reusable understanding, decisions, hypotheses and session history. Extract only what helps the selected purpose: a useful principle, actionable constraint or unresolved question, with exact source links and its limits. Do not manufacture consensus between contradictory sources. A recent summary is not automatically authoritative. Use the [knowledge template](../../templates/knowledge.md), adapting the existing note conventions and avoiding one new file per idea.

A synthesis request authorizes a sourced synthesis, not wholesale canonical-memory promotion. Keep interpretations provisional unless the user asks to retain confirmed current understanding. If updating existing understanding, read [the memory procedure](../../memory.md), preserve prior evidence and record meaningful changes. Keep pending contradictions visible. Do not merge/delete/rename source notes as incidental cleanup; broader consolidation belongs to the later audit/improvement mode.

When resurfacing older knowledge, explain its relevance to today's task and distinguish supported lessons from suggestions for reuse. Link source evidence and the useful project route. Use `mcc-link` for meaningful relationships or an Activation Map; a weak association stays proposed. Read back the result, verify its source links and route from/to the hub, and report what remains tentative. Honor no-save by returning the synthesis only in chat.
